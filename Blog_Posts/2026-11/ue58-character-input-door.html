직전 179장 교재 개정 시점까지 작업실(L_Work_08_Complete) 점검 기록에는 긍정적인 항목들만 적혀 있었습니다. 에디터 플레이(PIE)에서 BP_WorkCharacter가 Walking 모드와 중력 스케일 1로 서 있고, F키를 눌렀을 때 BP_WorkDoor가 100°로 열리고 BP_WorkLamp 가시성이 전환되며, 테스트용 W 입력에서 위치 변화가 잡혔다는 확인이었기 때문입니다.

그러나 사용자가 직접 플레이 모드에 들어가 키보드를 누르며 보행을 시도해 본 후속 상세 점검 단계에서 숨겨져 있던 세 가지 치명적인 사용성 문제가 한꺼번에 드러났습니다. 실제 키보드 WASD를 눌러도 캐릭터가 전혀 앞으로 가지 않고, 마우스를 움직이면 상하 시점이 반대로 뒤집히며, 문틀 폭이 좁아 캐릭터가 문 안으로 걸어 들어가지 못하는 현상이었습니다. 이번 글에서는 179장 단계의 부분 확인이 왜 오류를 놓쳤는지 짚어보고, 원인 파악과 수정 과정, 그리고 단발 자동 입력 도구의 한계를 보완하기 위해 4단계로 분리해 수행한 정밀 검증 기록을 공유하고자 합니다.

1. 179장 시점 부분 확인의 한계와 세 가지 복합 증상

왜 1차 확인에서는 문제를 놓치고 후속 점검에서 오류가 발견되었을까요. 가장 큰 이유는 초기 확인이 개별 블루프린트 상태나 API 단발 트리거 확인 위주였고, 실제 사용자가 키보드를 계속 누르며 마우스를 흔들고 문턱을 넘어 실내까지 진입하는 연속 시나리오를 거치지 않았기 때문입니다.

후속 정밀 테스트에서 확인된 구체적인 증상은 다음과 같았습니다.

  • 증상 1 (이동 입력 불능): 플레이 모드에서 W, A, S, D 키를 눌러도 캐릭터가 어느 방향으로도 전진·후퇴·좌우 이동하지 않았습니다.
  • 증상 2 (마우스 상하 반전): 마우스를 위로 올리면 시선이 하늘로 향해야 자연스럽지만 반대로 바닥을 향해 꺾이는 상하(Pitch) 반전이 일어났습니다.
  • 증상 3 (문틀 걸림 및 밀림): 문 비례를 살린 소형 작업실 입구 폭에 비해 캐릭터 충돌 캡슐이 너무 커서 문틀에 끼여 통과하지 못했으며, 문짝에 바짝 붙어 있는 상태에서 F키로 문을 열면 회전하는 문 메쉬 콜리전이 캐릭터를 옆으로 밀어내는 현상이 발생했습니다.
⚠️ 참고 (엔진 C++ 팝업 현상): 입력 디버깅 도중 에디터 내부에서 C++ 관련 소스/보기 메뉴가 잘못 트리거되어 Visual Studio 로그인 창과 .h 파일 연결 앱 선택 대화상자가 화면을 가로막는 소동도 한 차례 겪었습니다. 해당 부트캠프 프로젝트(Bootcamp_BaseProject)는 사용자 C++ 모듈이 전혀 없는 순수 Blueprint 및 에셋 기반 프로젝트이므로 해당 팝업 창을 모두 닫고 PIE 검증을 재개했습니다.

2. Key 핀 파싱 오류 수정, MouseY 반전 교정 및 캡슐 축소

Epic Games 공식 문서의 CharacterMovementComponent 및 입력 처리 구조를 기준으로 BP_WorkCharacter와 컴포넌트 수치를 하나씩 분해해 점검한 결과, 세 증상의 정확한 원인과 수정 지점을 찾아냈습니다.

원인 및 해결 1: Key 핀의 (KeyName=...) 직렬화 문자열 파싱 오류

원인 파악: BP_WorkCharacter 이벤트 그래프의 키 입력 노드를 살펴보니, Key 핀에 순수 키 이름 리터럴 대신 구조체 직렬화 문자열 형태인 (KeyName=...)이 잘못 기록되어 있었습니다. Unreal Engine 블루프린트 직렬화 파서가 이 문자열을 올바른 FKey 구조체로 복원하지 못하고 첫 글자 ( 등 잘못된 토큰으로 해석하면서 실제 키보드 입력 이벤트가 전혀 바인딩되지 않았던 것입니다. (특히 스크립트나 텍스트 기반 MCP 도구 호출로 Key 핀 기본값을 대입할 때 자주 겪을 수 있는 함정입니다.)

해결 과정: 잘못 들어간 (KeyName=...) 문자열을 모두 제거하고, 핀 값에 W, S, A, D, MouseX, MouseY 키 리터럴 값을 직접 전달하도록 수정한 뒤 블루프린트를 컴파일·저장했습니다.

원인 및 해결 2: MouseY 부호 반전과 1인칭 EyeCamera 설정

원인 파악: MouseY 축 입력 값이 AddControllerPitchInput 노드가 기대하는 부호 방향과 반대로 연결되어 있어, 마우스를 위로 밀 때 시점이 아래로 내려갔습니다.

해결 과정: Blueprint 그래프 중간에 0 - MouseY 뺄셈 연산을 배치해 부호를 반전시킨 뒤 AddControllerPitchInput에 연결했습니다. 아울러 1인칭 시점 카메라(EyeCamera)의 상대 높이를 Z = 72cm(눈높이)로 맞추고 Use Pawn Control Rotation 옵션을 활성화해 컨트롤러 회전과 카메라 상하·좌우 시점이 1:1로 연동되도록 정리했습니다.

원인 및 해결 3: 소형 문틀 통과를 위한 CapsuleComponent 축소

원인 파악: 5편에서 작업실 크기를 4×3.6m로 줄이고 문 메쉬(SM_door_Baked_0021)의 비균일 확대를 없애 원비례를 복원한 상태였는데, 캐릭터 루트 충돌 볼륨인 CapsuleComponent는 여전히 반지름 24cm(지름 48cm), 반높이 88cm(전체 높이 176cm)로 유지되어 좁아진 문틀 개구부와 부딪히고 있었습니다.

해결 과정: CapsuleComponent의 크기를 반지름 18cm(지름 36cm), 반높이 80cm(전체 높이 160cm)로 축소해 문을 비정상적으로 키우지 않고도 자연스럽게 통과할 수 있는 폭과 높이를 확보했습니다. 동시에 CharacterMovementComponent는 MOVE_Walking, GravityScale = 1, Walk Speed = 180, Step Height = 25로 설정해 작은 실내 공간에서 너무 빠르게 튀지 않고 문턱을 가볍게 넘을 수 있도록 맞췄습니다.

3. 자동 입력, 임시 연속 전진, 사용자 실조작의 4단계 분리 검증

이슈를 수정한 뒤 검수 과정에서 중요하게 지킨 원칙이 있습니다. 자동화된 에디터 입력 도구는 짧은 키 입력(tap)만 지원할 뿐, 사람이 W키를 2초간 꾹 누르며 문턱을 통과하는 연속 입력을 흉내 내지 못했습니다. 반대로 연속 전진 테스트를 위해 임시 값을 넣어둔 채 그대로 저장해 버리면, 수강생이 프로젝트를 열자마자 캐릭터가 알아서 걸어가는 오염된 파일이 배포됩니다.

이를 명확히 통제하기 위해 검증 절차를 다음 4단계로 분리하고, 모든 단계의 결과 JSON과 임시 값 원복 상태를 근거로 남겼습니다.

여기서 3단계 '열린 문 통과 검사' 출발 좌표를 문 바로 앞이 아닌 문 바깥 X = -320, Y = -40, Z = 82.15로 잡은 이유가 있습니다. 문짝에 바짝 밀착한 채로 F키를 눌러 문을 100°로 회전시키면, 회전 반경 안쪽에 있던 캐릭터 캡슐이 문 메쉬와 부딪혀 옆으로 밀려나는 물리 현상이 발생합니다. 이 회전 중 문 충돌 현상과 '이미 열린 문틀을 캐릭터가 정상 보행으로 통과하는가'라는 문제를 섞지 않기 위해 문 바깥에서 출발해 통과 여부를 따로 분리 검증했습니다.

4. 검증 결과 해석의 정확한 경계와 다음 편 예고

자동 단발 입력과 임시 전진 값 공급 후 재시작 원복(Velocity = 0), 그리고 사용자의 W키 직접 조작까지 확인함으로써 BP_WorkCharacter의 이동·시점·출입구 통과 오류는 깔끔하게 해결되었습니다. 다만 기술 문서 작성 시 검증 결과의 적용 범위를 과대 해석하지 않도록 다음 세 가지 경계를 분명히 구분해 두었습니다.

  • 문 통과 확인의 범위 제한: 사용자의 "문 안으로 정상적으로 들어감" 확인은 출입구 문 통과 버그가 수정되었음을 증명하는 것이지, 작업실 전체 디자인 품질(배치, 색감, 밝기)에 대한 포괄적 승인이나 실내 책상·의자·소파·서랍 사이 모든 동선에서의 끼임 부재를 보장하지 않습니다.
  • 문 밀착 개방 시 물리 밀림 정책: 문에 아주 가까이 붙은 상태에서 F키로 문을 열 때 옆으로 밀리는 현상을 입문 교육용 프로젝트 특성상 허용할지, 아니면 개방 애니메이션 동안 충돌을 일시 무시하는 보완 로직을 넣을지는 후속 검토 항목입니다.
  • Enhanced Input vs 직접 Key 핀 비교: 교재가 입문자의 노드 직관성을 위해 직접 Key 핀 연결 방식을 택한 것과 UE 5.8 표준 Enhanced Input(IA_Move, IA_Look, IMC_Default Negate Modifier) 사이의 설명 정렬 여부도 추후 강의 개편 시 검토 대상입니다.

이로써 1교시 입문부터 자연환경(2~4교시)과 실내 작업실·보행 인터랙션(5~7교시)까지의 난관들을 모두 정리했습니다. 이제 8시간 부트캠프의 마지막 8교시인 4장, Motion Design(모션 그래픽) 트랙으로 넘어갈 차례입니다. 다음 7편에서는 짙은 남색 스튜디오의 단순 3D 타이틀과 SignalGrid 168개 타일 플립 중간 버전을 거쳐, 최종 40×30 = 1,200개 타일 그리드가 공을 따라 상하 파동 및 누적 360° 회전을 수행한 뒤 원위치로 복귀하는 Motion Design Cloner·Effector 구현과 240프레임 궤적 정량 검증 기록을 살펴보겠습니다.
