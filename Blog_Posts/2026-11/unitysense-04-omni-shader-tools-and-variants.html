3편에서 ShaderLab/HLSL 전용 LSP를 구축해 F12 정의 이동과 다단계 #include 추적을 확보한 뒤, 실제 셰이더 편집 편의성을 한 단계 더 끌어올리기 위해 필요한 기능들을 점검했습니다. VS Code 마켓플레이스에는 Omni Shader Tools나 Shader languages support 같은 개별 셰이더 확장들이 존재하지만, 여러 셰이더 확장을 동시에 설치하면 언어 ID(shaderlab, hlsl)와 TextMate 문법, 포매터가 서로 충돌하는 경우가 잦습니다.

이번 글에서는 이미 구현된 LSP 기능과 겹치지 않는 영역만 선별해 UnitySense 내부로 통합한 배리언트 추적, 전처리기 키워드 Dimming, ShaderLab+HLSL 혼합 포매터, 그리고 Shader Explorer 뷰 구현 내용을 살펴보겠습니다.

2. 배리언트 수 CodeLens와 전처리기 Dimming 정교화

Unity 셰이더에서 #pragma multi_compile이나 #pragma shader_feature가 쌓이다 보면 의도치 않게 배리언트 수가 급격히 불어납니다. ShaderVariantCodeLensProvider는 각 Pass와 HLSLPROGRAM 블록의 키워드 그룹을 파싱해 전체 조합 수(각 그룹 길이의 곱)를 상단 CodeLens로 표시합니다. 또한 하단 상태바(Shader Keywords)에서 활성 키워드를 체크박스로 토글하면 shader-lsp로 unityBrain/setShaderKeywords 알림을 보내 비활성 #if 분기를 흐리게(Dimming) 표시합니다.

이 과정에서 eval 없이 동작하는 안전한 전처리기 조건 파서를 구현했는데, 테스트 중 두 가지 오작동이 발견되어 v1.1.4와 v1.1.6에서 수정했습니다.

  • Include-guard 자기 자신 Dimming 오류: 헤더 파일 최상단에 흔히 쓰는 #ifndef MY_HEADER_INCLUDED 직후 #define MY_HEADER_INCLUDED가 나오면, 평가 순서가 꼬여 헤더 본문 전체가 비활성 블록으로 흐려지는 증상이 있었습니다. Include-guard 패턴을 예외 처리해 정상 활성화되도록 수정했습니다.
  • #if 0 및 #define FOO 0 구분 오류: 매크로가 정의되어 있는지 여부(defined(FOO))와 값 평가(#if FOO)를 분리하지 않아 #define FOO 0이 참으로 평가되는 문제가 있었습니다. 정의 여부와 수치 평가를 분리하고 멀티라인 #elif 활성 줄 처리까지 보완했습니다.

3. 혼합 포매터, DSL 자동완성 및 미검증 항목 안내

shaderFormatter.ts는 Properties, SubShader, Pass, Tags, Stencil 같은 ShaderLab 영역과 HLSLPROGRAM...ENDHLSL 내부를 구분해 들여쓰기를 정리합니다. 구현 도중 Stencil { Pass Replace } 내부의 Pass 키워드가 SubShader의 Pass 블록 시작으로 오인되거나 블록 주석(/* ... */) 종료 줄에서 들여쓰기가 틀어지는 이슈를 발견해, 주석·문자열·Stencil 내부 마스킹을 적용하고 2회 연속 실행 시 변경점이 없는 멱등성 테스트를 통과시켰습니다. 실제 셰이더 파일에 적용해 본 들여쓰기 결과도 무난했습니다.

함께 추가한 기능으로는 Properties 어트리뷰트([HDR], [MainTexture] 등)·Tags·Blend·Stencil DSL 자동완성, URP/HDRP/Compute 스니펫, Properties와 CBUFFER_START(UnityPerMaterial) 간 SRP Batcher 정합성 진단, 그리고 unitySense.shaderExplorer 트리 뷰와 Shader Live Profiler(unitySense.testCurrentShader)가 있습니다.

⚠️ 주의: 실제 프로젝트 환경에서의 128 배리언트 초과 경고 동작과 Shader Live Profiler의 TMU/ALU 추정 부하 등급 분석은 현재 실전 테스트가 필요한 상태입니다. 이 항목들은 앞으로 실제 프로젝트에 적용해 사용하면서 점차 검증하고 보완해 나갈 예정입니다.

마무리하며

셰이더 관련 부가 기능들을 하나의 확장에 통합하면서 언어 ID 충돌 없이 포매팅과 키워드 분기 확인을 이어갈 수 있는 기반을 마련했습니다. 다만 Explorer 경고 임계치나 Live Profiler의 추정 정확도는 실제 복잡한 셰이더를 돌려봐야 체감할 수 있는 영역이므로, 실사용 피드백을 통해 다듬어 갈 계획입니다.
