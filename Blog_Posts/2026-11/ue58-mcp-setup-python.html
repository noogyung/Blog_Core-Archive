앞선 1편과 2편에서 살펴본 것처럼, 이번 Unreal Engine 5.8 부트캠프 교재와 프로젝트(Bootcamp_BaseProject)는 단번에 만들어진 것이 아니라 여러 차례 개정과 수정을 거치며 28개 맵과 181장 PPTX로 발전해 왔습니다. 흥미로운 점은 이 방대한 에디터 구성과 수정 작업에 사용된 자동화 인터페이스 역시 프로젝트 후반부에 중요한 전환점을 맞았다는 사실입니다.

작업 초기(67장~165장 단계)에는 아직 Unreal Engine 5.8 공식 MCP 서버가 연결되지 않은 상태에서 에디터 내부의 Unreal Python 명령을 이용해 씬 구축을 진행했습니다. 이후 사용자 요청에 맞춰 Epic Games의 공식 Unreal MCP 문서를 확인하고 엔진 내장 ModelContextProtocol 및 AllToolsets 플러그인을 활성화하면서, 모션 그래픽 및 MCP 개정 단계(182장 단계) 이후부터는 공식 MCP 도구 중심으로 작업 방식이 전환되었습니다. 이번 글에서는 UE 5.8 공식 Unreal MCP 설정 절차와 함께, 초기 Unreal Python 실행과 외부 Python HTTP 클라이언트를 혼동하지 않고 구별해 정리한 내용을 공유하고자 합니다.

1. UE 5.8 공식 Unreal MCP 아키텍처와 보안 경계

Unreal Engine 5.8에는 AI 에이전트나 외부 개발 도구가 표준 프로토콜을 통해 에디터 기능을 안전하게 호출할 수 있도록 공식 MCP 서버 구현체가 포함되어 있습니다. Epic Games 공식 문서 기준으로 이 구조는 크게 두 가지 플러그인의 조합으로 동작합니다.

  • ModelContextProtocol 플러그인: Unreal Editor 프로세스 내부에 로컬 HTTP 기반 MCP 서버(기본 엔드포인트 /mcp)를 구동하는 코어 백엔드입니다.
  • AllToolsets 플러그인: 액터 생성, 조명 설정, 머티리얼 인스턴스, 블루프린트 및 UMG 등 실제 에디터 조작 도구를 외부 에이전트에 노출하는 도구 묶음(Aggregator)입니다. 기본값은 비활성화(EnabledByDefault: false) 상태이므로 반드시 명시적으로 켜주어야 합니다.

런타임 측면에서 가장 눈여겨보아야 할 부분은 동시성 제어와 네트워크 보안 범위입니다. 공식 Unreal MCP 서버는 에디터 게임 스레드(Game Thread)의 상태 충돌을 막기 위해 들어오는 요청을 순차적으로 동기화하여 실행합니다. 또한 별도의 인증 토큰 레이어 없이 동일 로컬 머신(127.0.0.1) 루프백 환경 전용으로 설계되어 있으므로, 방화벽 개방이나 포트 포워딩을 통해 외부 네트워크에 서버 포트를 노출하는 행위는 피해야 합니다.

2. 작업 시점 분리와 'Python 클라이언트 vs Unreal Python' 구별

부트캠프 구축 이력을 기술할 때 가장 경계해야 할 오류는 두 가지입니다. 첫 번째로는 후반부에 도입한 공식 Unreal MCP 사용 이력을 초기 Unreal Python 작업 시점(67장~165장)으로 소급해 적는 왜곡이고, 두 번째로는 'MCP 호출 스크립트가 Python으로 작성되었다'는 이유만으로 이를 '에디터 내부 Unreal Python API 실행'과 동일시하는 기술적 혼동입니다.

flowchart LR
    Early["작업 초기 (67~165장): PythonEditorScriptPlugin"] -->|"에디터 내부 API 직접 실행"| Scene["UE 5.8 에디터 씬"]
    Agent["외부 AI 도구 / Python HTTP 클라이언트"] -->|"HTTP JSON-RPC (127.0.0.1:8000/mcp)"| Server["ModelContextProtocol 코어 서버"]

실제로 공식 Unreal MCP로 전환한 이후에도 테스트나 배치 작업을 자동화하기 위해 Python으로 HTTP JSON-RPC 요청 클라이언트를 작성해 http://127.0.0.1:8000/mcp 엔드포인트에 호출을 보낼 수 있습니다. 그러나 이는 외부 클라이언트가 네트워크 프로토콜(MCP)을 거쳐 에디터 내장 도구(AllToolsets)를 호출하는 구조일 뿐, 에디터 내부 파이썬 런타임(PythonEditorScriptPlugin)이 UObject에 직접 접근하는 방식과는 통신 계층 자체가 다릅니다.

적용 프로젝트 시점 초기~중간 개정 (67장 ~ 165장 단계) 모션·MCP 개정 (182장 단계) ~ 최종 통합본
실행 위치 및 주체 에디터 내부 PythonEditorScriptPlugin 외부 AI 에이전트 또는 Python HTTP 스크립트
통신 경로 엔진 내부 unreal 모듈 직접 호출 로컬 루프백 http://127.0.0.1:8000/mcp JSON-RPC
교출 기능 제어 범위 에디터 스크립트 API가 허용하는 내부 객체 접근 AllToolsets가 등록·노출한 표준 에디터 도구 호출
수동 조작 병행 여부 병행 (캡처 및 수동 구도 보정) 병행 (뷰포트 UI 정렬, 네이티브 기능, 스틸컷 캡처, 실제 PIE 키 확인)

마찬가지로 공식 MCP를 도입한 이후에도 모든 조작이 MCP만으로 이루어졌다고 과장해서는 안 됩니다. 뷰포트 구도 미세 정렬, 일부 에디터 네이티브 대화상자 조작, 181장 교재용 실제 UI 스크린샷 캡처, 그리고 실제 플레이 모드(PIE)에서의 키보드 연속 입력 테스트는 사람이 직접 화면을 보고 조작하는 과정을 반드시 병행했습니다.

3. Unreal Editor 5.8 공식 MCP 활성화 및 실제 연동 절차

수강생이 8교시 과정에서 MCP 서버 구동을 직접 확인하고, 강사나 프로젝트 제작자가 로컬 AI 에이전트를 에디터와 연결하기 위해 적용한 실제 설정 절차는 다음과 같습니다.

  1. MCP 플러그인 활성화 및 에디터 재시작: Unreal Editor 상단 메뉴의 편집(Edit) > 플러그인(Plugins)에서 검색창에 mcp를 입력하고 ModelContextProtocol(UI 표기: Unreal MCP)과 AllToolsets 도구를 활성화한 뒤 에디터를 재시작합니다. (또는 Bootcamp_BaseProject.uproject의 Plugins 목록에 직접 활성화 설정을 반영합니다.)
  2. 로컬 MCP 서버 기동: 에디터 하단 콘솔 명령창 또는 출력 로그(Output Log)에서 포트 번호를 지정해 서버를 엽니다. 반복 작업 시에는 Editor Preferences의 General > Model Context Protocol > Auto Start Server(또는 설정값 bAutoStartServer=True)를 활용할 수 있습니다.
  3. 클라이언트 설정 파일 등록: 프로젝트 루트의 .codex/config.toml에 로컬 서버 URL(http://127.0.0.1:8000/mcp)을 등록합니다. 공식 문서 기준으로 에디터 콘솔에서 ModelContextProtocol.GenerateClientConfig [ClientName] 명령을 실행해 ClaudeCode, Cursor, VSCode, Gemini, Codex용 설정 초안을 생성하는 기능도 지원합니다.
  4. 실제 도구 호출 확인 및 교재 예시 보존: 에디터와 클라이언트가 연결된 상태에서 구체(Sphere) 액터 생성 MCP 요청을 실행해 뷰포트 반영 여부를 검증하고, 그 실제 요청·응답 JSON 파일(Guides/MCP_공생성_요청.json, MCP_공생성_응답.json, MCP_실제명령_예시.json)을 교재 보조 자료로 함께 패키징했습니다.
ModelContextProtocol.StartServer 8000

콘솔에서 위 명령을 실행하면 출력 로그에 LogModelContextProtocol과 LogHttpServerModule: All listeners started 메시지가 찍히며, 연결된 LLM 서비스와 언리얼 라이선스 기술 관련 안내 경고가 함께 출력됩니다.

서버가 열린 상태에서 실제 구체 생성·배치 MCP 명령을 호출해 에디터 뷰포트 및 디테일 패널에 반영된 모습을 확인하고, 이 일련의 플러그인·콘솔·호출 결과 화면까지 교재 슬라이드에 그대로 수록했습니다.

4. MCP 도입 및 운용 과정에서 확인된 주요 이슈와 해결

실제 부트캠프 작업실, 블루프린트, 재질, PCG, 입력 및 참조 수정에 공식 Unreal MCP 도구를 적용하면서 단순 연결 외에 꼭 짚고 넘어가야 할 트러블슈팅 사례들이 나타났습니다.

서버 기동 후 AI 클라이언트에 에디터 도구가 노출되지 않는 현상

증상: ModelContextProtocol.StartServer 8000 명령이 정상 동작해 HTTP 리스너까지 열렸음에도 불구하고, 연결된 AI 에이전트 측 도구 목록에 액터 배치나 에셋 수정 관련 툴이 하나도 나타나지 않았습니다.

원인 파악: ModelContextProtocol 플러그인은 프로토콜 서버 백엔드만 제공할 뿐 실제 에디터 기능을 담고 있지 않습니다. 실제 도구 어그리에이터 역할을 맡는 AllToolsets 플러그인은 기본 설정상 비활성화되어 있기 때문에 별도로 켜지 않으면 빈 도구 목록만 반환됩니다.

해결 과정 및 결과: 두 플러그인(ModelContextProtocol + AllToolsets)을 함께 체크해 활성화하고 에디터를 재시작한 뒤에야 정상적으로 에디터 도구들이 노출되어 작업실과 PCG 씬 수정에 활용할 수 있었습니다.

MCP 호출 성공 응답과 디스크 상태·에셋 참조 동기화의 괴리

증상: 이후 시리즈 8편에서 상세히 다룰 맵 경로 통합 과정에서, MCP의 이동(move) 및 수정 도구로부터 성공 응답을 받았음에도 에디터 외부 디스크에 구경로 파일이 남아 있거나 Data Asset·시퀀서 참조가 이전 맵을 가리키는 문제가 발생했습니다.

원인 파악: MCP 도구 호출의 성공 응답은 해당 에디터 API 함수가 예외 없이 반환되었다는 뜻이지, 언리얼 패키지 직렬화, Redirector 정리, 미로드 패키지 간 참조 갱신, 물리적 디스크 잔존 파일 제거까지 끝마쳤음을 보장하지 않기 때문입니다.

해결 과정 및 결과: MCP 도구를 통해 액터나 자산을 수정한 뒤에는 반드시 명시적 저장을 실행하고, 참조 뷰어 스캔과 구경로 문자열 검사, 대상 맵 재오픈 확인을 독립적인 검증 절차로 분리해 운용하도록 작업 규칙을 정비했습니다.

5. 남은 검증 과제와 다음 편 예고

공식 Unreal MCP 도입 덕분에 후반부 작업실과 입력 수정, 맵 참조 디버깅, 실제 요청·응답 교재 예시 제작까지 에디터 기반 자동화 파이프라인을 체계적으로 활용할 수 있었습니다. 다만 현재까지 확인된 범위를 넘어 다음 항목들은 후속 확인 대상으로 남겨두었습니다.

  • 다른 강의실 PC 환경에서 배포 ZIP만 압축 해제해 UE 5.8로 최초 실행했을 때, ModelContextProtocol·AllToolsets 플러그인과 .codex/config.toml 설정이 추가 수동 조작 없이 바로 연동되는지 검증
  • 교재 실습 시나리오에서 bAutoStartServer=True 자동 기동 방식과 콘솔 ModelContextProtocol.StartServer 8000 수동 기동 방식 중 어느 쪽을 기본 권장 흐름으로 둘지 최종 확정
  • 보존된 MCP 요청·응답 JSON 예시 파일들을 외부 공개 문서에 인용할 때 로컬 경로 표현이나 포트 안내가 깔끔히 정리되었는지 검토

기획(1편), 28개 맵·181장 교재 프레임워크(2편), 공식 Unreal MCP 환경(3편)이라는 세 가지 기반이 마련되었으니, 이제 부트캠프의 본격적인 첫 번째 실습 트랙으로 들어갈 차례입니다. 다음 4편에서는 자연환경(01_Environment) 트랙에서 Electric Dreams 에셋을 선별 재구성하고, 바위 표면은 제외하며 지면 중심 식생을 배치하는 PCG(5B)와 레벨 세트 데이터 추출 및 광역 스캐터링(5C~5E) 구축기를 살펴보겠습니다.

Unreal Engine 5.8 에디터 작업에 공식 MCP 서버나 Python 자동화를 도입하실 때, 여러분은 에디터 UI 수작업과 AI 도구 호출 사이의 검증 경계를 어떤 체크리스트로 구분하고 계신지 궁금합니다.
