앞선 1편에서 다루었듯, 파이썬으로 자동 생성한 텍스트 위주 기본 템플릿 PPT 초안만으로는 비전공 입문자가 Unreal Engine 5.8 에디터의 수많은 패널과 메뉴 사이에서 길을 잃지 않고 3대 결과물을 따라 만들 수 없었습니다. 실제로 초기 샘플 구성을 검토해 본 결과, 구매하거나 무료로 배포되는 에셋 샘플 레벨을 그대로 열어 촬영하는 방식 역시 교육 재현성이 크게 떨어진다는 문제점이 확인되었습니다.

초보자가 원하는 것은 이미 화려하게 완성된 데모 월드를 구경하는 일이 아니라, 아무것도 없는 빈 레벨(00_Empty)을 연 뒤 어느 메뉴의 몇 번 버튼을 눌러 어떤 에셋과 수치를 넣으면 눈앞의 장면이 만들어지는지 하나씩 따라 할 수 있는 실물 안내서입니다. 이번 글에서는 초기 61장·67장 뼈대에서 출발해 중간 버전들을 거치며 최종 181장 PPTX와 28개 단계별 체크포인트 맵, 289개 의존 패키지로 교재와 프로젝트를 전면 재구성하고 정량 검증한 과정을 정리해보고자 합니다.

1. 구매 샘플 의존 배제와 정방향(0 → 완성) 체크포인트 원칙

초기 씬 개발 단계에서는 Fab에서 내려받은 Electric Dreams 샘플이나 기존 데모 프로젝트 복사본 위주로 구도를 잡으려는 시도도 있었습니다. 그러나 실제 교재 피드백을 거치며 구매 샘플 원본 촬영 방식의 한계가 분명히 드러났습니다. 샘플 맵은 이미 수천 개의 액터와 복잡한 서브시스템이 얽혀 있어, 입문자가 빈 레벨에서 동일한 구도를 직접 재현하려 할 때 어떤 단계로 쌓아 올려야 하는지 구조가 보이지 않았기 때문입니다.

이에 따라 제작 방향을 근본적으로 전환하여 다음과 같은 두 가지 설계 원칙을 세웠습니다.

  1. 강의 프로젝트 내부 독립 재구축: 외부 샘플 프로젝트 채로 촬영하지 않고, 선별한 핵심 에셋만을 단일 강의 프로젝트(Bootcamp_BaseProject)의 Content/_Bootcamp/90_Library/ 경로로 가져와 빈 레벨에서부터 직접 배치하고 수치로 재현할 수 있게 구성했습니다.
  2. 완성 구도 선검토 후 정방향 단계 분해: 제작자 입장에서는 먼저 최종 완성 구도(Complete)를 만들어 조명·밀도·카메라 구도 품질을 검토하고, 이후 교육용으로 단계별 요소를 분리해 나가는 방식(필요 시 완성 씬에서 역으로 요소를 덜어내며 체크포인트 검증)을 적용했습니다. 반면 수강생이 실제로 따라가는 진행 방향은 반드시 00_Empty(0개 액터)에서 시작해 완성 레벨로 나아가는 정방향으로 구성했습니다.
💡 캡처 시점 경로 안내: 위 초기 화면 스틸컷의 콘텐츠 브라우저 하단 경로에는 작업 중간 시점 폴더 구조인 _Bootcamp > 01_Environment > Maps > Lessons가 표시되어 있습니다. 최종 배포 버전에서는 Guided/Lessons 중복 하위 폴더를 제거하고 모든 맵을 각 트랙의 Maps 폴더 직하위로 통합했습니다.

자동 검사가 보장하지 않는 미검증 경계

자동 검증 JSON의 claim_boundary와 native_powerpoint_verified: false 항목이 분명히 명시하듯, 위 통과 결과는 PPTX XML 패키지 구조와 스크립트 기준 레이아웃 좌표 검사를 뜻할 뿐 다음 세 영역까지 대변하지는 않습니다.

  • PowerPoint 데스크톱 앱 네이티브 실행: 실제 Microsoft PowerPoint 애플리케이션을 열어 181장 전체 슬라이드쇼 전환과 맑은 고딕 시스템 렌더링을 육안으로 전수 확인하는 과정은 미검증 상태입니다.
  • 발표자 노트 181개 전수 검토: 패키지 검사에서 notes_parts_skipped: 181로 기록된 것처럼, 슬라이드 하단 발표자 노트의 문맥 정확성은 자동 검사의 검증 범위 밖입니다.
  • 슬라이드 138 경고 실물 확인: 0.2357 × 0.1279in 겹침 경고가 실제 발표 화면에서 글자 가림을 유발하는지 여부는 PowerPoint 앱에서 직접 확인해야 합니다.

5. 정리 및 다음 편 예고

기획 단계의 추상적인 8개 교시 설계를 실제 에디터 화면 번호와 00_Empty~Complete 체크포인트 28개 맵, 289개 의존 패키지, 181장 UI 상세 교재로 구체화하면서, '초보자도 따라 할 수 있는 재현성'과 '버전별 검증 경계의 분리'라는 두 가지 기준을 확립했습니다.

한편, 이렇게 수백 개의 에셋과 28개 맵, 181장 교재를 구축하고 수정하는 과정이 순수 수작업이나 초기 스크립트로만 진행된 것은 아닙니다. 이후 이어지는 4~8편의 실외 자연환경·실내 작업실·모션 그래픽 구축과 참조 복구 작업 상당수는 작업 후반부에 도입한 UE 5.8 공식 Unreal MCP 서버를 통해 수행·점검되었습니다. 각 실습 트랙의 구체적인 씬 구축기로 들어가기 전에, 먼저 다음 3편에서 ModelContextProtocol 및 AllToolsets 플러그인 활성화부터 포트 8000 서버 기동, 그리고 초기 Unreal Python 직접 제어와 외부 Python HTTP MCP 클라이언트를 구별해 운용한 자동화 기반을 살펴보겠습니다.

실습 중심의 기술 교재를 만들 때, 여러분은 버전이 여러 번 바뀌는 과정에서 구버전 스크린샷과 최신 프로젝트 수치 사이의 불일치를 어떤 검증 기준이나 해시 체계로 통제하고 계신지 궁금합니다.
