지난 10편에서는 긴 기술 문서와 무한 스크롤 웹페이지에서 발생하던 429 Resource Exhausted 쿼터 제한을 큐 후방 재진입(Re-enqueuing) 지속 루프와 중앙 통합 프롬프트 빌더로 해결하여, 누락 없는 완주 번역 파이프라인을 구축했습니다.

그러나 이후 웹페이지 번역 테스트 중, 특정 시점부터 Gemini API 호출이 전면 실패하며 콘솔에 다음과 같은 404 에러가 반환되는 현상이 확인되었습니다: 

[WebTranslator] 배치 1 오류 — 스킵하고 계속 진행
Error: 404 This model models/gemini-2.5-flash is no longer available to new users

구글이 실험용 프리뷰 모델의 서비스를 종료(Deprecated)하거나 모델명을 변경하면서, 소스 코드 내에 고정 문자열로 작성해 두었던 모델 식별자가 유효하지 않게 된 것입니다.

이번 글에서는 클라이언트 코드 내 하드코딩 방식의 구조적 한계를 짚어보고, 사용자의 API 키를 활용해 현재 계정에서 즉시 호출 가능한 최신 Flash 모델을 실시간으로 식별하고 캐싱하는 동적 모델 탐색(Dynamic Model Fetch) 아키텍처 구축 과정을 정리하고자 합니다.

1. 모델 하드코딩의 구조적 취약점

클라우드 기반 LLM 서비스는 주기적으로 신규 모델을 릴리스하며 실험용 엔드포인트를 폐기하거나 버전을 갱신합니다.

모델 관리 방식 동작 메커니즘 운영 리스크 및 특징
정적 하드코딩 코드 내 models/gemini-2.5-flash 문자열 고정 공급자의 모델 정책 변경 시 즉시 404 에러로 서비스 중단
실시간 동적 탐색 GET /v1beta/models 호출 후 가용 모델 선별 클라이언트 코드 수정 없이 변경된 최신 모델 자동 적응

초기 개발 당시에는 속도와 성능을 고려하여 특정 프리뷰 모델명을 하드코딩하여 사용했습니다. 그러나 공급자 측에서 해당 프리뷰 모델의 엔드포인트를 내리는 순간, 모든 번역 요청이 중단되는 단일 실패점(SPOF)으로 작용했습니다.

2. 초기 접근 방식의 한계: 하드코딩의 반복

AI 어시스턴트에게 모델 404 오류 수정을 요청했을 때 작성된 초기 코드는 다음과 같았습니다. 

// gemini.js: 또 다른 고정 문자열 적용 (임시 코드)
const GEMINI_MODEL = "gemini-1.5-flash-latest"; // 모델 명칭 정책 변경 시 재발 위험 존재

구조적 한계 분석

단순히 현재 동작하는 다른 모델명으로 교체하는 것은 임시방편에 불과합니다. 공급자가 네이밍 규칙을 다시 변경하거나 접미사 정책을 바꿀 경우 동일한 404 Not Found 에러가 발생할 수밖에 없습니다.

⚠️ 핵심 결함: 외부 AI 서비스의 모델 수명 주기는 클라이언트가 제어할 수 없으므로, 고정 문자열에 의존하는 방식은 장기적인 안정성을 보장하기 어렵습니다.

3. 해결 방안: 실시간 가용 모델 동적 탐색 (`getValidGeminiModel`)

고정 문자열 의존성을 제거하고, 사용자의 API Key로 구글 모델 엔드포인트(GET /v1beta/models)를 직접 호출하여 현재 계정에서 실제로 호출 가능한 Flash 모델을 실시간으로 선별하도록 파이프라인을 개선했습니다.

필터링 기준 검사 로직 목적
1. 텍스트 생성 지원 supportedGenerationMethods.includes("generateContent") 임베딩 전용 모델 등 비번역 모델 제외
2. 고속 Flash 계열 model.name.includes("flash") 웹페이지 번역에 적합한 저지연 모델 추출
3. 레거시 모델 배제 !model.name.includes("legacy") 지원 중단 예정인 구형 모델 우선 제외

4. 메모리 캐싱 및 안전 Fallback 아키텍처

동적 모델 탐색을 매 번역 요청마다 수행하면 불필요한 네트워크 왕복 지연(RTT)이 발생합니다. 이를 방지하기 위해 세션 메모리 캐싱과 네트워크 오류 시 3단계 안전 Fallback을 적용했습니다. 

// src/background/engines/gemini.js: 실시간 가용 모델 동적 탐색 및 캐싱 모듈
let cachedModelName = null;

export async function getValidGeminiModel(apiKey) {
  // 1. 이미 검증된 모델명이 메모리에 캐시되어 있다면 즉시 반환
  if (cachedModelName) {
    return cachedModelName;
  }

  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models?key=${apiKey}`
    );
    const data = await response.json();

    if (data.models && Array.isArray(data.models)) {
      // 2. generateContent를 지원하는 flash 계열 최신 모델 필터링
      const flashModel = data.models.find(
        (m) =>
          m.supportedGenerationMethods?.includes("generateContent") &&
          m.name.includes("flash") &&
          !m.name.includes("legacy")
      );

      if (flashModel) {
        // "models/gemini-1.5-flash" -> "gemini-1.5-flash" 정제
        cachedModelName = flashModel.name.replace("models/", "");
        console.log(`[WebTranslator] 최신 가용 Gemini 모델 자동 탐색 성공: ${cachedModelName}`);
        return cachedModelName;
      }
    }
  } catch (err) {
    console.warn("[WebTranslator] 모델 목록 동적 조회 실패, 기본 Fallback 모델을 사용합니다:", err);
  }

  // 3. 네트워크 단절 또는 API 메타데이터 조회 실패 시 최후의 안전 기본값
  return "gemini-1.5-flash";
}

5. 검증 결과 및 운영 안정성

  1. 404 에러 방지: 공급자가 특정 모델을 내리거나 신규 버전을 배포하더라도, 확장 프로그램이 첫 실행 시 자동으로 가용한 최신 Flash 모델을 식별하여 호출했습니다.
  2. 무중단 브라우징: 사용자가 API 키만 설정해 두면 백그라운드에서 모델 가용성을 자동으로 확인하므로, 외부 정책 변경에 영향받지 않는 번역 안정성을 확보했습니다.

마무리하며

동적 모델 탐색을 통해 모델 가용성을 안정화했으나, 스팀 커뮤니티나 레딧처럼 특수문자, 이모지, 복잡한 인라인 HTML 태그가 다수 포함된 긴 포럼 글을 번역할 때 간헐적으로 빈 문자열 응답이 반환되며 번역 프로세스가 멈추는 현상이 확인되었습니다.
