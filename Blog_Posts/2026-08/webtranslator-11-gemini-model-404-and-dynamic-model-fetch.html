지난 10편에서는 긴 기술 문서와 무한 스크롤 웹페이지에서 발생하던 429 Resource Exhausted 쿼터 제한을 큐 후방 재진입(Re-enqueuing) 지속 루프와 중앙 통합 프롬프트 빌더로 해결하여, 대용량 번역의 완주율을 100%로 끌어올렸습니다.

프로젝트 초기에는 gemini-2.5-flash 모델명을 코드 내에 고정하여 사용했으나, 사용자가 본인의 용도와 선호에 따라 원하는 모델을 직접 지정할 수 있도록 옵션 페이지 내 사용자 직접 모델 입력 방식으로 빠르게 전환했습니다.

그러나 사용자가 직접 지정한 프리뷰 모델의 사용량이 모두 소진되거나, 구글 측에서 해당 프리뷰 모델의 엔드포인트를 사전 예고 없이 종료(Deprecated)했을 때 콘솔에 다음과 같은 404 에러가 발생하며 번역이 전면 중단되는 문제가 나타났습니다: 

[WebTranslator] 배치 1 오류 — 스킵하고 계속 진행
Error: 404 This model models/gemini-2.5-flash is no longer available to new users

이번 글에서는 사용자가 지정한 모델의 가용성 소진 문제와, 단순히 임의의 상위 모델로 자동 대체할 때 발생하는 유료 모델(GPT 등)의 고비용 과금(High-Cost) 리스크를 살펴보고, 이를 안전하게 통제하는 비용 방어형 동적 가용성 검증 파이프라인 구축 과정을 다루어 보겠습니다.

1. 사용자 직접 입력 모델과 가용성 소진 한계

다양한 LLM 엔진을 지원하기 위해 사용자가 설정창에서 직접 모델명(예: gemini-1.5-flash, gpt-4o-mini)을 입력하도록 구조를 개편했습니다.

모델 지정 방식 장점 발생 가능한 장애 상황
사용자 직접 입력 원하는 최신 모델 자유 선택 가능 지정한 모델의 쿼터 소진 또는 공급자의 모델 폐기 시 404 발생
무조건적 자동 Fallback 중단 없는 번역 지속 가능 유료 상위 모델로 임의 우회 시 예상치 못한 막대한 비용 청구 발생

사용자가 입력한 모델이 404 에러나 사용량 제한에 도달했을 때, 단순히 "아무 가용 모델이나 자동으로 찾아서 대체"하도록 설계하면 매우 위험한 부작용이 뒤따릅니다.

2. 무분별한 자동 Fallback의 함정: 유료 모델 고비용 과금 리스크

이 문제는 OpenAI GPT나 Anthropic 등 유료 API를 직접 결제하여 사용하는 환경에서 겪은 경험에서 비롯되었습니다.

만약 사용자가 저렴한 가성비 모델(예: Mini 또는 Flash 계열)을 지정해 두었는데, 시스템이 에러를 감지하고 임의로 가용한 상위 모델(예: GPT-4o 정식 버전, Gemini Pro 등)로 자동 승격하여 수백 문단의 웹문서를 번역해 버린다면 단 몇 분 만에 수십 달러 이상의 API 비용이 청구되는 비용 참사가 발생할 수 있습니다.

⚠️ 핵심 리스크: 클라이언트 확장 프로그램에서 외부 유료 API 모델을 다룰 때는, 사용자 동의 없는 임의의 모델 상향 대체(Auto-Escalation)를 절대로 허용해서는 안 됩니다.

3. 해결 방안: 계정별 가용 모델 실시간 검증 (`getValidGeminiModel`)

따라서 동적 모델 탐색은 사용자의 명시적 제어권을 침해하지 않는 범위 내에서만 엄격히 격리 적용되도록 아키텍처를 설계했습니다:

  1. 사용자 지정 모델 1순위 존중: 사용자가 설정한 모델이 정상 동작할 때는 일체의 자동 변경 없이 해당 모델을 그대로 사용합니다.
  2. 동일 가성비 티어(Flash) 내 검증: 모델 사용량 소진이나 404 발생 시, GET /v1beta/models 조회를 통해 오직 저지연·무료/초저가 Flash 계열 내에서만 최신 가용 모델을 안전하게 식별합니다.
  3. 고비용 상위 모델 원천 차단: Pro나 유료 상위 모델은 자동 대체 후보군에서 원천 배제하여 과금 위험을 0%로 통제합니다.
필터링 조건 검사 로직 비용 및 안정성 방어 목적
1. 콘텐츠 생성 지원 supportedGenerationMethods.includes("generateContent") 임베딩 등 비번역 모델 제외
2. Flash 가성비 티어 한정 model.name.includes("flash") 고비용 Pro/상위 모델로의 임의 과금 우회 원천 차단
3. 레거시/만료 모델 배제 !model.name.includes("legacy") 지원 중단 예정인 구형 엔드포인트 제외

4. 실시간 모델 검증 및 세션 캐싱 모듈 구현

매 번역 요청마다 불필요한 네트워크 조회가 발생하지 않도록 세션 메모리 캐싱을 적용한 검증 모듈을 완성했습니다. 

// src/background/engines/gemini.js: 고비용 과금 방어형 가용 모델 검증 모듈
let cachedModelName = null;

export async function getValidGeminiModel(apiKey, userConfiguredModel = "") {
  // 1. 사용자가 명시적으로 입력한 유효 모델이 있다면 최우선 적용
  if (userConfiguredModel && userConfiguredModel.trim().length > 0) {
    return userConfiguredModel.trim();
  }

  // 2. 이미 검증된 Flash 모델명이 메모리에 캐시되어 있다면 즉시 반환
  if (cachedModelName) {
    return cachedModelName;
  }

  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models?key=${apiKey}`
    );
    const data = await response.json();

    if (data.models && Array.isArray(data.models)) {
      // 3. 고비용 모델을 배제하고 오직 안전한 Flash 계열 최신 모델만 선별
      const safeFlashModel = data.models.find(
        (m) =>
          m.supportedGenerationMethods?.includes("generateContent") &&
          m.name.includes("flash") &&
          !m.name.includes("legacy")
      );

      if (safeFlashModel) {
        cachedModelName = safeFlashModel.name.replace("models/", "");
        console.log(`[WebTranslator] 가용 Flash 모델 자동 확인: ${cachedModelName}`);
        return cachedModelName;
      }
    }
  } catch (err) {
    console.warn("[WebTranslator] 모델 메타데이터 조회 실패, 기본 안전 모델을 사용합니다:", err);
  }

  // 4. 네트워크 단절 또는 조회 실패 시 최후의 기본 안전 모델
  return "gemini-1.5-flash";
}

5. 검증 결과 및 비용 방어 효과

  1. 사용자 제어권 완벽 보장: 사용자가 지정한 모델이 정확히 호출되며, 임의의 모델 승격으로 인한 과금 사고를 완전히 차단했습니다.
  2. 404 가용성 안전 복원: 미지정 또는 쿼터 소진 상황에서도 Flash 계열 내에서만 안전하게 가용 모델을 식별하여 비용 부담 없이 번역을 지속했습니다.

마무리하며

사용자 모델 지정 방식과 비용 방어형 동적 검증 파이프라인을 구축하여 안정성을 확보했으나, 스팀 커뮤니티나 레딧처럼 특수문자, 이모지, 복잡한 인라인 HTML 태그가 다수 포함된 긴 포럼 글을 번역할 때 간헐적으로 "번역 응답이 비어 있습니다"라는 빈 문자열 응답이 오며 번역이 지연되는 현상이 발생했습니다.
