지난 10편에서는 긴 기술 문서와 무한 스크롤 웹페이지에서 발생하던 429 Resource Exhausted 쿼터 제한을 큐 후방 재진입(Re-enqueuing) 지속 루프와 중앙 통합 프롬프트 빌더로 해결하여, 대용량 번역의 완주율을 100%로 끌어올렸습니다.

그러나 번역 엔진 안정화 과정에서 또 다른 복병을 마주했습니다. 구형 모델을 하드코딩하여 쓰다가 발생한 404 에러를 해결하려던 중, AI의 조언대로 도입한 '실시간 자동 모델 선택' 기능이 되려 고비용 모델을 마구잡이로 호출하여 무료 쿼터를 파괴하고 OpenAI 선결제 크레딧을 순식간에 탕진하는 과금 참사를 일으킨 것입니다.

이번 글에서는 404 에러의 발생 원인부터, AI가 추천한 자동 탐색 기능이 왜 치명적인 비용 폭탄으로 이어졌는지, 그리고 이를 해결하기 위해 초가성비 모델 직접 고정 방식과 모델 탐색 헬퍼 도구로 아키텍처를 전면 전환한 과정을 정리해 보고자 합니다.

1. 하드코딩된 구형 모델의 한계와 404 장애

개발 초기에는 Gemini 번역을 위해 코드 내에 gemini-2.5-flash 모델명을 고정 문자열로 하드코딩해 두었습니다.

그러나 gemini-2.5-flash는 구형 실험용 프리뷰 모델로서 기본 제공되는 무료 허용량이 매우 적었습니다. 결국 웹서핑 중 쿼터가 순식간에 바닥나거나, 공급자 측에서 해당 프리뷰 엔드포인트를 사전 예고 없이 종료(Deprecated)하면서 콘솔에 다음과 같은 404 에러가 쏟아졌습니다: 

[WebTranslator] 배치 1 오류 — 스킵하고 계속 진행
Error: 404 This model models/gemini-2.5-flash is no longer available to new users

이 404 에러를 해결하기 위해 AI 어시스턴트에게 문제 해결을 맡겼고, 여기서부터 예상치 못한 두 번째 참사가 시작되었습니다.

2. AI의 '실시간 자동 모델 선택' 추천과 10달러 과금 참사

AI 어시스턴트는 404 에러를 방지하겠다며 구글 API(GET /v1beta/models)를 호출하여 실시간으로 가용한 모델을 자동으로 탐색하여 번역 런타임에 즉시 꽂아 넣는 자동 모델 선택 모듈을 제안했습니다. 

// translator.js: 모델별 단가/쿼터를 모르는 위험한 자동 선택 (오류 코드)
async function getRuntimeModel(apiKey) {
  const models = await fetchAvailableModelsFromAPI(apiKey);
  // 치명적 결함: 가격이나 쿼터 정책을 전혀 고려하지 않고 아무 모델이나 골라잡음!
  return models.find(m => m.supportsGeneration).name; 
}

발생한 치명적인 과금 및 쿼터 폭사 분석

이 자동 탐색 모듈은 각 AI 모델의 단가(Pricing)와 쿼터(Quota) 정책을 전혀 알지 못했습니다:

  • Gemini 무료 쿼터 고갈: gemini-3.5-flash-lite와 gemini-2.5-flash는 단가와 분당 허용량이 완전히 다른데, AI가 임의로 무거운 모델을 선택해 버려 15 RPM 무료 쿼터가 순식간에 고갈되고 또다시 에러가 발생했습니다.
  • OpenAI $10 선결제금 증발: OpenAI(GPT)의 경우 사태가 훨씬 심각했습니다. 선결제 크레딧 방식인 OpenAI 계정에서, 가장 저렴한 최신 초경량 모델인 gpt-5.4-nano를 사용하지 않고 코드 누락으로 고비용 모델인 gpt-4o가 호출되면서 충전해 둔 10달러가 순식간에 소진되는 과금 참사가 발생했습니다.
⚠️ 핵심 교훈: 클라이언트 번역 루프에서 모델을 임의로 자동 변경(Auto-Escalation)하도록 방치하는 것은 외부 유료 API 환경에서 매우 위험한 과금 사고를 초래합니다.

3. 해결책 1: 자동 선택 전면 폐기 및 '사용자 직접 모델 고정' 전환

번역 런타임 내의 위험한 자동 모델 선택기를 전면 폐기하고, 사용자가 검증된 초가성비 모델을 설정창에서 직접 명시하여 고정 사용하는 방식으로 전환했습니다.

실제 번역 환경에서는 10편에서 구축한 지수 백오프와 MutationObserver 디바운스 배치 큐가 이미 요청 빈도를 촘촘히 제어하고 있으므로, 가성비 모델을 고정하기만 하면 비용과 쿼터 문제가 완벽히 해결되었습니다:

엔진 고정 적용 모델 실제 운영 결과 및 비용
Google Gemini gemini-flash-lite-latest 15 RPM 무료 쿼터 내에서 429/404 에러 없이 100% 완주 (비용 0원)
OpenAI GPT gpt-5.4-nano 10만 자 번역 시 약 $0.01 수준의 극도로 저렴한 비용으로 경제적 번역 달성

4. 해결책 2: 가용 모델 조회를 '옵션 헬퍼 도구'로 변형 분리

사용자가 직접 모델명을 입력하도록 변경하자, "현재 제공되는 최신 모델명이 정확히 무엇인지 알기 어렵다"는 사용성 문제가 생겼습니다.

이에 AI가 만들었던 실시간 가용 모델 조회 API(GET /v1beta/models)를 번역 실행 경로에서 완전히 떼어내어, 옵션 페이지에서 사용자가 현재 쓸 수 있는 최신 모델 목록을 손쉽게 검색하고 복사할 수 있는 '모델 탐색 헬퍼(Model Helper)' 도구로 변형 재활용했습니다. 

// src/options/model_helper.js: 옵션 UI 전용 가용 모델 탐색 헬퍼
export async function fetchAvailableModelList(apiKey) {
  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models?key=${apiKey}`
    );
    const data = await response.json();

    if (data.models && Array.isArray(data.models)) {
      // 텍스트 생성을 지원하는 모델 목록을 필터링하여 사용자에게 안내
      return data.models
        .filter(m => m.supportedGenerationMethods?.includes("generateContent"))
        .map(m => m.name.replace("models/", ""));
    }
  } catch (err) {
    console.warn("[ModelHelper] 모델 목록 조회 실패:", err);
    return ["gemini-flash-lite-latest", "gemini-1.5-flash"];
  }
}

5. 검증 결과 및 운영 안정성

  1. 과금 참사 원천 봉쇄: 번역 런타임이 무단으로 모델을 바꾸지 않고 지정된 초가성비 모델만 호출하므로, OpenAI 크레딧 소진 리스크를 완전히 제거했습니다.
  2. 무료 완주 및 사용자 편의성 확보: Gemini는 gemini-flash-lite-latest로 비용 없이 완주하며, 모델명을 찾고 싶을 때는 옵션 창의 헬퍼를 통해 원클릭으로 최신 모델을 확인하여 지정할 수 있게 되었습니다.

마무리하며

모델 가용성 헬퍼와 초가성비 모델 고정을 통해 비용과 404 장애를 모두 정복했으나, 스팀 커뮤니티나 레딧처럼 특수문자, 이모지, 복잡한 인라인 HTML 태그가 다수 섞인 긴 포럼 글을 번역할 때 간헐적으로 "번역 응답이 비어 있습니다"라는 빈 문자열 응답이 오며 번역이 멈춰버리는 무한 로딩 버그가 나타났습니다.
