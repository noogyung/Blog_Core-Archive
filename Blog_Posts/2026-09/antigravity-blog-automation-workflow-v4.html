블로그 자동화 파이프라인을 구축하면서 마주했던 숙제는 단순히 AI로 초안을 빠르게 찍어내는 것이 아니었습니다. 앞선 1편에서 구글 NotebookLM의 맥락 손실 한계를 겪고 Antigravity 단독 루프로 전환했으며, 2편에서는 프롬프트 지시서와 CDN 캐시 퍼지를 정비했고, 3편에서는 제어 영역(BlogDocs)과 데이터 저장소(Blog_Core-Archive)를 물리적으로 분리하는 분산 아키텍처를 세웠습니다.

하지만 시스템을 갖추고 실제로 글을 연재하기 시작하자, 운영 관점에서 완전히 새로운 갈증들이 수면 위로 올라왔습니다. 복잡한 시스템 구조를 설명할 때 외부 그래픽 툴 없이 깔끔한 벡터 다이어그램을 본문에 그릴 방법이 필요했고, 수십 편에 달하는 연재물을 관리하면서 본문 링크가 깨지지 않는 동적 시리즈 내비게이션이 절실했습니다.

무엇보다 구글 블로그스팟의 기본 댓글 시스템이 지닌 한계가 컸습니다. 기본 댓글도 익명 작성이 가능하기는 하지만, 무인 봇이나 악성 스팸을 걸러내는 검출 기능이 전무하여 광고 댓글에 무방비로 노출되고, 테마와 겉도는 낙후된 디자인에다 익명 작성자가 답글 알림을 받을 본인의 이메일이나 웹사이트 정보를 남길 수 없다는 결정적인 문제가 있었습니다.

이번 글에서는 이러한 한계들을 극복하기 위해 테마 차원에서 직접 통합한 Mermaid.js 벡터 다이어그램 엔진, 중앙 집중식 카탈로그 기반 동적 시리즈 내비게이션, 그리고 Vercel·Neon PostgreSQL·Cloudflare Turnstile 기반의 Waline 서버리스 댓글 시스템 구축 및 Median UI 완전 일체화 과정을 실제 DDL 쿼리와 설정 코드까지 포함하여 상세히 정리해보고자 합니다.

1. 세대별 파이프라인 진화와 현재의 워크플로우

자동화 시스템은 한 번에 완성되지 않았습니다. 실제 포스팅을 발행하고 테마를 수정하는 과정에서 드러난 구조적 결함들을 하나씩 걷어내며 다음과 같은 단계로 진화해 왔습니다.

구분 1세대 (v1) 2세대 (v2) 3세대 (v3) 현재 상태 (v3.1+)

현재 워크플로우는 5개의 정규 슬래시 커맨드로 명확하게 역할이 분리되어 있습니다. 특히 검증 과정에서 코드가 변경되거나 피드백이 발생했을 때, /2_피드백 커맨드가 지식 파일(Knowledge)과 이미 작성된 HTML 초안을 양방향으로 동시에 수정해 줌으로써 문서와 실제 게시글 간의 괴리를 원천 차단했습니다.

💡 팁: AI에게 포스팅 작성을 일임할 때 자율성을 과도하게 부여하면 이전 편의 링크나 미래의 글 제목을 임의로 날조하는 환각이 발생합니다. 동작 영역을 엄격한 스킬 가드레일로 통제하고, 정적인 데이터는 단일 기준 카탈로그로 관리하는 것이 파이프라인 안정성의 핵심입니다.

2. 텍스트 기반 다이어그램 시각화: Mermaid.js 1:1 자연 배율 통합

기술 블로그를 운영하다 보면 파이프라인의 데이터 흐름이나 아키텍처를 한눈에 보여주는 도식이 필수적입니다. 이전에는 외부 그래픽 툴로 이미지를 일일이 내보내어 업로드하거나 AI 이미지 생성기에 의존해야 했는데, 내용이 조금만 바뀌어도 도식 전체를 다시 제작해야 하는 번거로움이 컸습니다.

이에 따라 블로그스팟 본문에 마크다운 형태의 <pre class="mermaid"> 코드 블록을 작성하면 브라우저 클라이언트가 즉시 고화질 SVG 벡터로 렌더링하는 방식을 테마에 이식했습니다.

도입 과정의 레이아웃 충돌과 트러블슈팅

하지만 Median UI 1.7 테마에 Mermaid 라이브러리를 주입하자마자 여러 가지 시각적 충돌이 발생했습니다.

가장 먼저 눈에 들어온 부분은 다이어그램이 본문 영역 안에서 돋보기로 보아야 할 정도로 작게 축소되어 출력되는 현상이었습니다. 원인을 분석해보니 Median UI 테마가 기본 코드 블록인 pre 태그에 부여해 둔 여백과 폰트 크기 스타일을 Mermaid 래퍼가 그대로 상속받고 있었습니다.

여기에 테마 전역 CSS에서 아이콘 크기를 맞추기 위해 선언해 둔 svg { width: 24px; height: 24px; } 스타일이 Mermaid가 생성한 복잡한 SVG 다이어그램까지 24픽셀 크기로 찌그러뜨리는 문제가 겹쳤습니다. 이로 인해 다이어그램 노드 내부의 텍스트가 박스 경계를 뚫고 넘치거나 폰트 크기가 들쭉날쭉해지는 현상이 연쇄적으로 일어났습니다.

1:1 자연 배율과 92vw×88vh 극장형 Lightbox 모달의 안착

초기에는 너비를 580px로 강제 고정하는 방식으로 대응했으나, 이는 단순한 다이어그램이 불필요하게 가로로 늘어나거나 반대로 가로가 긴 순서도가 잘리는 또 다른 부작용을 낳았습니다. 최종적으로 다음과 같이 스타일과 스크립트를 정비했습니다.

  1. 1:1 자연 배율(Natural Scale) 정규화: 억지스러운 가로폭 고정을 제거하고 width: auto !important; max-width: 100% !important;를 부여하여 다이어그램 고유의 종횡비와 벡터 크기를 본문 너비 안에서 자연스럽게 유지하도록 구성했습니다.
  2. 폰트 상속 및 정규화: 노드 내부 foreignObject div와 text 요소가 본문 테마 폰트를 상속받고 13px 크기로 일관되게 중앙 정렬되도록 CSS를 격리했습니다.
  3. 극장형 Lightbox 모달 연동: 다이어그램을 클릭하면 화면의 92vw × 88vh 크기를 차지하는 대형 모달 창이 열리며, 원본 해상도의 선명한 벡터 그래픽으로 확대되어 모바일 실기기(360px~412px 뷰포트)에서도 가로 스크롤이나 터치 줌으로 쾌적하게 확인할 수 있도록 구현했습니다.

실제 블로그 본문에서 렌더링되는 아키텍처 흐름도를 Mermaid 코드로 표현하면 다음과 같습니다.

3. 중앙 집중식 카탈로그 기반 동적 시리즈 네비게이션

2세대 파이프라인까지는 각 게시글의 HTML 하단에 이전 편: slug-a, 다음 편: slug-b 형태의 메타데이터를 작성해 두었습니다. 하지만 글을 연재하다 중간에 보충 편을 끼워 넣거나 목차 구조를 변경하게 되면, 이미 발행된 이전 글들의 HTML을 일일이 열어 링크를 수정해야만 했습니다. 심지어 아직 쓰이지도 않은 미래 편의 슬러그를 AI가 그럴듯하게 날조하여 404 페이지로 연결되는 일도 빈번했습니다.

단일 기준 카탈로그(_series.yaml / _series.json) 체계

이 문제를 완전히 해결하기 위해 개별 게시글 본문에서 시리즈와 관련된 일체의 하드코딩 링크와 미래 예측 메타데이터(Next Slug, series_total 등)를 완전히 제거했습니다. 대신 본문 끝에는 단 한 줄의 컨테이너만 선언하도록 규칙을 세웠습니다.

<!-- 시리즈 네비게이션 컨테이너 (JS로 동적 렌더링) -->
<nav class="series-nav"></nav>

테마에 내장된 자바스크립트는 페이지가 열릴 때 GitHub Raw 저장소의 _series.json 카탈로그와 블로그스팟 라벨 피드를 실시간으로 조회하여 브라우저 단에서 동적으로 처리합니다.

초기 구현 당시에는 위 화면처럼 피드 조회 조건과 슬러그 파싱의 결함으로 인해 이전 편과 다음 편 카드가 둘 다 동일한 3편을 가리키거나 순서가 뒤엉키는 렌더링 버그가 발생했습니다.

또한 초기 프로토타입 단계에서 AI에게 스타일링을 일임했을 때, 위 화면처럼 테마 전역 규칙을 무시하고 임의의 배경색과 어색한 아이콘을 주입하여 다크/라이트 모드 간 색상 호환성을 깨뜨리는 문제도 겪었습니다. 이를 바로잡기 위해 테마 고유의 CSS 변수 체계를 온전히 준수하도록 정규화하고, 피드 필터링 로직을 정비했습니다.

나아가 20편이 넘어가는 장기 연재물(WebTranslator 개발기 등)의 경우, 방대한 목차가 본문을 너무 길게 차지하지 않도록 챕터별 접이식 아코디언 목차를 완벽하게 구현했습니다.

  • 이전/다음 글 자동 계산: 카탈로그에 명시된 토픽 배열 순서를 읽어 현재 글의 앞뒤 편을 정확하게 찾아 카드로 렌더링합니다. (순서가 바뀌거나 새 글이 추가되어도 카탈로그 파일만 수정하면 모든 글의 이전/다음 링크가 즉시 갱신됩니다.)
  • 탭 기반 UI 분리: '📌 시리즈 목록' 탭에는 정규 순서 카드와 전체 목차를 배치하고, '✨ 관심이 있을 만한 글' 탭에는 현재 시리즈 글을 제외한 블로그의 추천 글을 분리 노출합니다.
  • 장기 연재물 챕터 아코디언: 챕터별로 묶인 접이식 아코디언 목차를 제공하여 독자가 원하는 단계로 쉽게 이동할 수 있도록 구성했습니다.

4. 구글 블로그의 한계 돌파: Waline 서버리스 댓글 시스템 구축

구글 블로그스팟의 기본 댓글 시스템도 익명 작성을 허용할 수는 있습니다. 하지만 스팸 봇을 걸러내는 방어 체계가 전무하여 광고 댓글에 무방비로 노출되고, 테마와 어울리지 않는 낙후된 룩앤필에다 익명 작성자가 답글 알림을 받을 본인의 이메일이나 웹사이트 정보를 남길 수 없다는 결정적인 한계가 있었습니다.

그 대안으로 선택한 것이 오픈소스 서버리스 댓글 솔루션인 Waline v3였습니다. 무엇보다 기술 블로그 운영에 있어 다음과 같은 독보적인 장점들을 제공했습니다.

  • Markdown 문법 완전 지원: 인라인 코드, 블록 코드, 굵게, 기울임, 링크, 인용구 등 마크다운 문법을 온전히 지원하여, 독자와 필자가 단순한 한 줄 텍스트를 넘어 소스코드 스니펫이나 포맷팅된 기술적 의견을 자유롭게 나눌 수 있습니다.
  • 이미지 첨부 및 외부 링크 지원: 에디터 툴바를 통해 스크린샷이나 참조 다이어그램 이미지를 바로 첨부할 수 있어, 버그 리포트나 트러블슈팅 상황에서 시각적 증거를 공유하며 깊이 있는 소통이 가능합니다.
  • 서버리스 비용 0원 인프라: 백엔드는 Vercel Serverless Function, 데이터베이스는 Neon PostgreSQL, 스팸 및 무인 봇 방어는 Cloudflare Turnstile을 결합하여 무료 티어 안에서 안전하고 강력한 독립형 댓글 시스템을 완성할 수 있습니다.

인프라 구축 및 권한 확보 7단계

실제 인프라를 올리는 과정에서 공식 문서만으로는 알기 어려웠던 실전 복병들과 핵심 설정 내역입니다.

  1. Cloudflare Turnstile 위젯 발급:
    방문자가 귀찮은 퍼즐을 풀 필요 없이 백그라운드에서 인간임을 검증하는 Turnstile 위젯을 생성했습니다. 여기서 핵심은 Domain 목록에 실제 블로그 주소(예: blog.yourdomain.com)뿐만 아니라 Vercel 고정 대표 주소(예: your-waline.vercel.app)를 함께 등록해야 한다는 점이었습니다. (도메인을 누락하면 가입 화면에서 차단 에러가 발생합니다.)
  2. Vercel 원클릭 배포와 모노레포 함정:
    Waline의 전체 GitHub 모노레포를 그대로 포크하여 Vercel에 연결하면 빌드 산출물 경로(dist)를 찾지 못해 빌드가 실패합니다. 반드시 서버 배포 전용으로 경량화된 공식 example 템플릿 레포지토리(walinejs/waline/example)를 사용하여 Vercel 프로젝트를 생성해야 합니다.
  3. Neon PostgreSQL 연동과 가상 섀도우 계정 격리 탈출:
    Vercel 내장 Storage 탭에서 원클릭으로 Neon DB를 생성한 후 'Open in Neon'을 누르면 인증 메일이 발송되지 않고 콘솔에 진입할 수 없는 기현상이 발생했습니다. Vercel이 사용자 이메일과 매핑되지 않는 임의의 GitHub OAuth 가상 계정으로 DB를 프로비저닝했기 때문이었습니다. 이 문제는 neon.tech 공식 홈페이지로 이동하여 GitHub 소셜 로그인을 직접 수행함으로써 해결되었습니다. 실제 스토리지 대시보드가 정상적으로 표시되며 데이터베이스 제어권을 온전히 확보할 수 있었습니다.
  4. Neon SQL Editor에서 테이블 수동 초기화 (실제 실행 DDL):

5. Median UI 1.7 테마 완전 일체화와 인터랙션 고도화

외부 위젯을 테마에 단순히 삽입하면 폰트, 여백, 다크 모드 전환 시 위젯만 하얗게 뜨는 등 블로그 전체의 디자인 완성도를 심각하게 해칩니다. 방문자가 외부 위젯임을 눈치채지 못할 정도로 테마와 완전한 시각적 일체감을 이루도록 커스텀을 진행했습니다.

다크/라이트 모드 CSS 변수 1:1 매핑

Median UI 테마는 html 태그가 아닌 body.nB[data-theme='dark'] 선택자를 통해 다크 모드를 제어합니다. 테마에 내장된 색상 변수들을 Waline의 내부 CSS 변수에 1:1로 매핑하여 테마 스위치를 누르는 즉시 댓글 영역도 부드럽게 색상이 동기화되도록 수정했습니다.

/* Median UI 1.7 전용 Waline CSS 변수 매핑 */
#waline {
  --waline-theme-color: var(--themeLink);
  --waline-color: var(--contentC);
  --waline-bgcolor: var(--contentBg);
  --waline-bgcolor-light: var(--contentBg-alt);
  --waline-border-color: var(--contentBd-color);
  --waline-disable-bgcolor: var(--contentBg-alt);
  --waline-avatar-size: 42px;
}

body.nB[data-theme='dark'] #waline {
  --waline-color: var(--contentC);
  --waline-bgcolor: var(--contentBg);
  --waline-bgcolor-light: var(--contentBg-alt);
  --waline-border-color: var(--contentBd-color);
}

미니멀 3분할 게스트 폼 및 불필요한 메타 은닉

기본 Waline UI는 닉네임, 이메일, 웹사이트 입력창 위에 영문 라벨이 크게 붙어 있어 세로 공간을 과도하게 차지했습니다. 상단 라벨 텍스트를 숨기고 세 입력창을 가로 3분할(33.3%)로 배치한 뒤, MutationObserver를 활용해 '닉네임', '이메일(알림용)', '웹사이트' 한글 Placeholder를 인풋 내부로 자연스럽게 주입했습니다.

또한 프로필 아바타 주변의 원형 테두리 위치가 어긋나거나 닉네임이 세로로 줄바꿈되는 버그를 잡고, 모바일 가독성을 저해하던 대댓글 점선 인용선(.wl-card .wl-quote)과 불필요한 OS/브라우저 메타 정보 배지(.wl-meta)를 숨겨 정갈한 미니멀리스트 룩을 완성했습니다.

에디터 사용성 최적화와 이모티콘 CSS 격리 트러블슈팅

실제 사용 테스트를 거치면서 기본 Waline 에디터와 테마 스타일 간에 발생한 여러 세부 결함들을 정밀하게 바로잡았습니다.

  1. 에디터의 패널 우측 이탈 및 최소 높이 최적화:
    Waline 기본 CSS가 텍스트 입력창(#waline-comments .wl-editor)에 box-sizing: content-box와 width: calc(100% - 1em)를 적용하고 있어, 테마의 내부 패딩(15px)과 더해져 에디터 폭이 패널 경계를 약 30px 초과하여 우측으로 삐져나오는(리사이즈 핸들이 박스 바깥에 위치) 현상이 있었습니다. 이를 해결하기 위해 box-sizing: border-box !important; width: 100% !important; margin: 0 !important;를 부여하여 패널 내부에 완벽히 안착시켰습니다. 아울러 지나치게 높았던 초기 에디터 높이(기본 8.75em)를 min-height: 3.5em;(약 60px)로 컴팩트하게 줄여 1~2줄의 가벼운 단문 댓글도 부담 없이 작성할 수 있도록 최적화했습니다.
  2. 실시간 글자 수 카운터(Word Counter) 연동 버그 해결:
    입력창 하단의 0 Words 글자 수 카운터가 한글 조합(IME)이나 커스텀 이벤트 처리 환경에서 숫자가 0에 멈추어 갱신되지 않던 현상을 에디터 input 이벤트 리스너와 동기화하여 실시간 집계가 정상 동작하도록 보강했습니다.
  3. 이모티콘/GIF 창의 플로팅 모달화:
    기본 이모티콘 팝업(.wl-emoji-popup)이 에디터 하단으로 밀려나며 패널의 overflow: hidden에 잘리고 배경이 투명해져 가독성이 훼손되던 문제를 해결하기 위해, 에디터 툴바 상단에 떠오르는 불투명 카드 형태의 플로팅 모달 팝오버(position: absolute; bottom: 100%;)로 재배치하고 입체적인 그림자(box-shadow)를 부여했습니다.
  4. 테마 전역 스타일 간섭으로 인한 이모티콘 100% 가로 왜곡 버그 해결:
    Mermaid에서 겪었던 전역 SVG 24px 간섭과 마찬가지로, Median UI 테마 전역의 article img { width: 100%; display: block; } 스타일이 댓글 내부의 <img class="wl-emoji">까지 강제 상속시키는 참사가 발생했습니다. 이로 인해 위 화면처럼 이모티콘이 문장 중간에 들어가지 못하고 강제로 줄바꿈되며 가로 100%로 납작하게 찌그러져 늘어났습니다. 댓글 전용 CSS에서 #waline-comments img.wl-emoji { display: inline-block !important; width: 1.25em !important; height: 1.25em !important; margin: 0 2px !important; vertical-align: middle !important; }를 선언하여 완벽한 인라인 이모지 렌더링을 복원했습니다.

Turnstile 중복 렌더링 무한 대기와 플로팅 팝오버

Waline과 Cloudflare Turnstile을 연동하는 과정에서 가장 까다로웠던 버그는 댓글 연속 작성 시 발생하는 1~2분 타임아웃 지연 현상이었습니다. 댓글을 하나 작성하고 나면 Waline이 입력 폼 컴포넌트를 리렌더링하는데, 기존에 마운트되었던 Turnstile 인스턴스를 정상적으로 소멸시키지 않아 Turnstile has already been rendered 에러를 뿜으며 멈추어 버렸습니다.

이를 억지로 우회하기 위해 글로벌 window.turnstile 객체를 가로채는 스크립트를 작성하면, Cloudflare의 api.js 내부 초기화 루틴이 꼬이면서 토큰 발급 콜백이 유실되어 2분 가까이 무한 로딩이 걸렸습니다.

💡 해결책: 무리한 전역 객체 가로채기를 모두 걷어내고, 스크립트 헤더에 id='cf-turnstile-script'를 주어 정적으로 단 한 번만 로드되도록 고정했습니다. 그리고 렌더링 직전 Turnstile 공식 API인 turnstile.remove(widgetId)를 명시적으로 호출하여 이전 인스턴스를 파괴한 후 새 위젯을 마운트하는 훅을 구현함으로써 연속 댓글 작성을 지연 없이 즉시 통과시켰습니다.

또한 위 화면처럼 150px×140px 크기의 네모난 Turnstile 캡차 상자가 인라인으로 끼어들어 글자 수와 전송 버튼을 밀어내는 레이아웃 파괴 현상을 해결하기 위해, 캡차 컨테이너에 position: absolute를 부여하여 Submit 버튼 상단에 깔끔하게 떠오르는 플로팅 팝오버 형태로 UI를 개편하고 비어있을 때는 완전 은닉 처리했습니다.

메인 슬라이더 4번 실시간 댓글 연동 및 하이브리드 승격

댓글 시스템의 도입 효과를 블로그 전면에 반영하기 위해, 홈 화면 상단의 메인 슬라이더 4번 슬롯을 Waline API와 실시간으로 연동했습니다.

  1. 실시간 비동기 조회: 메인 슬라이더가 렌더링될 때 Waline의 /api/comment?type=count 엔드포인트를 호출하여 최근 글들의 실제 댓글 수를 확인합니다.
  2. 하이브리드 자동 승격: 댓글이 1개 이상 달린 게시글이 감지되면 해당 글을 즉시 `화제의 글` 슬라이드로 자동 승격시킵니다. 만약 모든 게시글의 댓글 수가 0개라면, 0개짜리 글을 억지로 띄우는 대신 최근 30일 조회수 2위 글을 `추천글` 뱃지로 유연하게 전환(fallback)합니다.
  3. 인기글 기간 통일 및 3종 중복 방지: 블로그스팟 인기글 집계 파라미터를 공식 규격인 LAST_MONTH(최근 30일)로 통일하고, 최신글·인기글·화제의 글 슬라이드가 동일한 글을 중복해서 가리키지 않도록 1위부터 3위까지 글을 순차 배정하는 중복 방지 알고리즘을 테마 스크립트에 탑재했습니다.

마무리하며

1세대 단순 텍스트 변환 파이프라인에서 출발했던 여정이 어느덧 4편에 이르렀습니다. 제어 영역과 데이터 저장소를 나눈 분산 아키텍처 위에 Mermaid.js 벡터 렌더링과 단일 기준 카탈로그 기반 동적 시리즈 내비게이션을 얹고, 마지막 퍼즐이었던 Waline 독립형 서버리스 댓글 시스템까지 테마 깊숙이 내재화함으로써 마침내 기술적으로 완전한 자립형 블로그 파이프라인의 틀을 갖추게 되었습니다.

외부 서비스에 의존하지 않고 Vercel, Neon PostgreSQL, Cloudflare Turnstile이라는 무료 서버리스 티어들을 정교하게 조립하여 고성능의 개인화 블로그를 완성해가는 과정은 홈랩과 엔지니어링의 본질적인 즐거움을 다시금 일깨워 주었습니다.

혹시 유사하게 구글 블로그스팟이나 정적 사이트에 Waline 댓글 시스템을 이식하시면서 Vercel 콜드 스타트나 Turnstile 중복 렌더링 문제를 겪으셨다면, 어떤 방식으로 해결하셨는지 하단 댓글로 자유롭게 의견을 남겨주시면 큰 도움이 되겠습니다. 본 포스팅에 적용된 구조나 스크립트에 대한 궁금증도 언제든 환영합니다.
