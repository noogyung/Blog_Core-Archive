윈도우 10 환경에서는 기본적으로 단축키를 이용해 스피커나 헤드셋 등 오디오 출력 장치를 즉각적으로 전환하는 기능을 지원하지 않습니다. 이를 해결하기 위해 여러 서드파티 앱들을 시도해 보았으나, 백그라운드 상주 시 오작동하거나 딜레이가 발생하는 등 제대로 동작하지 않는 경우가 많았습니다. 이에 인터넷 검색으로 계속 헤매는 것보다 AI의 도움을 받아 직접 맞춤형 앱을 제작하는 것이 훨씬 효율적일 것이라 판단하여 개발을 시작하게 되었습니다.

이번 글에서는 초기에 Python을 활용하여 빠르게 프로토타입을 검증한 뒤, 20MB 이상의 메모리 점유 및 실행 속도 제약을 극복하기 위해 최종적으로 C++ Win32 Native API 기반으로 포팅하여 1.5MB의 극초경량화를 달성한 전체 개발 과정을 상세히 살펴보고자 합니다.

1. 파이썬 기반 초기 기획 및 프로토타입 구현

최초 기획 단계에서는 신속한 개발과 로직 검증을 위해 Python을 채택했습니다. pystray 모듈로 시스템 트레이를 구현하고, comtypes 모듈을 통해 문서화되지 않은 윈도우 내부 COM 인터페이스(IPolicyConfig)를 호출하여 기본 장치를 전환하는 방식이었습니다.

글로벌 훅 마비와 pynput 도입

초기 버전에서는 keyboard 라이브러리를 사용하여 사용자의 지정 단축키(예: Ctrl+Alt+Shift+Win+S)를 감지하도록 구성했습니다. 그러나 keyboard 모듈이 윈도우 저수준 키보드 훅을 가로채는 방식이 불안정하여, 한 번 누른 뒤 시스템 전체의 키보드 입력이 먹통이 되는 치명적인 결함이 발생했습니다.

이를 해결하기 위해 더 안정적인 pynput 모듈로 단축키 엔진을 전면 교체하였고, 키를 누르는 과정에서 발생하는 가상 키코드(83) 오류 등을 상태 머신 도입을 통해 정밀하게 캡처하도록 고도화하여 파이썬 기반 앱으로서의 결함을 대부분 수정할 수 있었습니다.

2. 메모리 점유율과 억지 최적화의 한계

파이썬 런타임 특성상 앱이 백그라운드에 상주하는 동안 약 20~23MB의 메모리를 지속적으로 점유했으며, PyInstaller로 빌드된 실행 파일의 크기 역시 약 32MB에 달했습니다.

이를 최적화하기 위해 Windows API의 SetProcessWorkingSetSize를 호출해 메모리를 OS에 강제로 반환하는 워킹셋 트리밍을 시도했습니다. 하지만 이러한 억지 최적화는 pystray의 Win32 메시지 펌프 루프를 블로킹하여 시스템 트레이 아이콘을 마비시키는 부작용을 낳았습니다.

⚠️ 주의: Python 프로세스 내에서 가비지 컬렉션을 우회하거나 억지로 메모리 페이지를 디스크로 스왑 아웃(Swap-out)시키는 행위는 실시간 이벤트 루프를 처리하는 UI 스레드에 치명적인 블로킹을 유발할 수 있습니다.

3. C++ Win32 Native API로의 전면 포팅

파이썬의 태생적 한계를 극복하기 위해, 검증이 끝난 로직을 바탕으로 C++ Win32 Native API 환경으로 앱을 전면 재작성하기로 결정했습니다. 설계가 완료된 작은 사이드 프로젝트를 타 언어로 마이그레이션하는 과정은 AI를 활용함으로써 아주 손쉽게 진행할 수 있었습니다.

  • 상주 메모리: 23MB → 1.5MB (약 93% 절감)
  • 실행 파일 크기: 32MB → 439KB (약 1/73 축소)
  • 콜드 부팅 속도: 1.5초 → 0초 (딜레이 제로)

모든 외부 의존성을 제거하고 Shell_NotifyIconW 및 IPolicyConfig를 직접 호출함으로써 성능적 한계를 완벽히 해결했습니다.

4. 저수준 키보드 훅(WH_KEYBOARD_LL)을 통한 간섭 차단

C++ 전환 후, 단축키 설정 팝업창에서 사용자가 새로운 핫키를 등록하기 위해 키보드를 캡처할 때, 기존 OS에 등록된 단축키(예: 윈도우 검색창을 띄우는 Win+S)가 그대로 시스템에 전파되어 실행되는 간섭 현상이 발생했습니다.

이를 해결하기 위해 설정 창 활성화 상태에서 WH_KEYBOARD_LL 저수준 훅을 일시적으로 설치하여 해결했습니다.

  1. 훅 설치: SetWindowsHookExW(WH_KEYBOARD_LL)를 통해 모든 키 이벤트를 낚아챕니다.
  2. OS 전파 차단: 키 입력 감지 시 return 1을 반환하여 OS나 타 응용프로그램으로 이벤트가 전달되는 것을 완전히 차단합니다.
  3. 입력 확정 및 훅 해제: 모든 수식어 키와 일반 키에서 손을 떼었을 때(WM_CLOSE) 핫키를 확정하고 UnhookWindowsHookEx를 호출해 안전하게 훅을 반환합니다.
